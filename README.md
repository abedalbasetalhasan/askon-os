# AskON OS

لوحة لإدارة المهام والملاحظات لفريق AskON، مبنية كصفحة ويب ثابتة وتتصل بـ Supabase للمستخدمين والبيانات والتحديثات الحية.

## تشغيلها وربطها بـ Supabase

1. أنشئ مشروعاً جديداً في Supabase، ثم افتح **SQL Editor** والصق محتوى `supabase/schema.sql` وشغّله كاملاً.
2. من **Authentication > Users** أنشئ حسابك بالبريد وكلمة مرور. عند إنشائه سيُبنى ملفه الشخصي تلقائياً.
3. من SQL Editor نفّذ أمر منح الإدارة الموجود في آخر `schema.sql` بعد استبدال البريد ببريدك.
4. من **Project Settings > API** خذ **Project URL** و**publishable key** (أو anon key للمشاريع القديمة).
5. انسخ `config.example.js` باسم `config.js`، ثم ضع القيمتين فيه. الملف مستثنى من Git عمداً.
6. افتح `index.html` عبر خادم ويب ثابت، وسجّل الدخول. لا تعتمد على النقر المزدوج للملف أثناء الاختبار، لأن بعض المتصفحات تقيد وحدات وخدمات الويب عند الفتح من القرص.

## مشاركة الفريق

- أضف كل عضو من **Authentication > Users** في Supabase. ينشئ المشغّل ملفه الشخصي تلقائياً؛ لا يحتاج العضو إلى مفاتيح Supabase.
- كل مستخدم مسجّل يمكنه إضافة وتعديل المهام والملاحظات؛ المدير وحده يستطيع حذفها أو تعديل أدوار أعضاء الفريق.
- لا تضع أبداً `service_role` أو secret key داخل `config.js` أو GitHub. المفتاح المخصص للمتصفح يكون آمناً فقط مع سياسات RLS الموجودة في المخطط.

## GitHub والنشر

ارفع هذا المجلد كمستودع **خاص** على GitHub. قبل تفعيل GitHub Pages أضف `config.js` كملف إعداد للنشر داخل بيئة الاستضافة أو أنشئ نسخة نشر محلية منه؛ لا ترفعه إلى المستودع. يمكن نشر الموقع على Vercel أو Netlify أو GitHub Pages، لكن GitHub Pages لا يدعم متغيرات سرية وقت التشغيل لصفحة HTML ثابتة، ولذلك يبقى الـ publishable/anon key فقط في نسخة النشر. الحماية الفعلية للبيانات تكون عبر RLS، وليست بإخفاء هذا المفتاح.

## فحوصات قبل الإطلاق

1. سجّل دخول المدير وأنشئ مهمة وملاحظة.
2. أنشئ مستخدماً عادياً، وسجّل به، وتأكد من وصول التحديث خلال ثوانٍ.
3. تأكد أن المستخدم العادي لا يستطيع حذف عنصر أو ترقية نفسه إلى مدير.
4. من Supabase افتح **Database > Replication** وتأكد أن الجداول الثلاثة مفعّلة للتحديثات الحية.
